同频 MedEcho · 后端主导的 Agent 重构提示词
把“前端 Demo + 模型转发器”改成“有 Agent Runtime 的后端应用”
============================================================

我是这份 Agent 的设计负责人。
这次不加一堆页面，也不做“后端 CRUD 外壳”。

这次做的是：

  把 MedEcho 的 Agent Runtime 放到后端。

  后端负责状态、规则、工具、模型、分享、权限、审计和降级。

投入比例建议：

  后端 70%
  Agent 运行时 20%
  UI 10%

如果只能记住一句话：

  后端不是给前端配的数据库，后端就是 Agent 本身。

============================================================
三、判断：后端就是 Agent Runtime
============================================================

现在的 `server.js` 做的是：

- 静态文件服务；
- /api/llm 代理；
- /api/geo 代理；
- /api/exam-fees。

它不是业务后端，因为：

- 没有数据库；
- 没有会话；
- 没有档案；
- 没有权限；
- 没有分享快照；
- 没有限流；
- 没有审计；
- 没有 Agent Loop。

所以“缺后端”翻译过来是：

  缺一个能承载 Agent 状态、工具、规则、记忆、分享和降级的运行时。

后端组件与 Agent 角色的对应关系：

| 后端组件 | Agent 角色 |
|---|---|
| Session | 身份与连续性 |
| Case Store | 工作记忆 |
| Turn Service | 对话循环 |
| Safety Engine | 安全守门员 |
| Tool Registry | 动作空间 |
| Model Gateway | 推理与表达 |
| Report Service | 计划生成 |
| Share Service | 交接 |
| Trace / Audit | 可观测与反思 |
| Rate Limit | 资源边界 |

不要把 Agent 做成“前端里的一段 prompt”。
Agent 的运行时必须在服务端。

============================================================
五、服务端 Agent Loop
============================================================

唯一对话入口：

  POST /api/cases/:id/turn

请求：

{
  "message": "用户原话",
  "selectedOption": "可选",
  "clientTurnId": "幂等键"
}

服务端顺序：

1. 校验 session 和 case 所有权。
2. 读取 Case File。
3. 追加用户 turn（幂等）。
4. 抽取结构化事实；抽不出的写 unknowns。
5. 跑 Safety Engine（确定性规则优先）。
6. 如果 emergency：立即返回急诊动作，停止追问。
7. Coordinator 决定下一步：
   - ASK_ONE_QUESTION
   - BUILD_PLAN
   - HANDOFF
   - EMERGENCY
   - DONE
8. 如需模型，调用 Model Gateway。
9. 校验模型输出：字段、科室白名单、禁忌词。
10. 写回 Case File、turn、trace。
11. 返回下一步动作和更新后的 Case File。

响应：

{
  "ok": true,
  "data": {
    "caseId": "c_...",
    "action": "ask|emergency|plan|handoff|done",
    "question": null | {
      "id": "q_...",
      "text": "一个问题",
      "options": ["选项1", "选项2", "说不清"]
    },
    "caseFile": { ... },
    "degraded": false,
    "source": "ai|rule",
    "trace": [
      { "step": 1, "agent": "safety", "action": "assess", "ms": 12 }
    ]
  }
}

服务端伪代码：

async function turn(caseId, input, session) {
  const c = await cases.getOwned(caseId, session.id);
  await turns.appendUser(c.id, input, input.clientTurnId);
  await facts.extractAndMerge(c, input);
  const safety = safetyEngine.assess(c);
  if (safety.emergency) {
    await traces.write(c.id, safety);
    return emergencyResponse(safety);
  }
  const action = coordinator.decide(c, safety);
  if (action.type === 'ASK_ONE_QUESTION') {
    return askResponse(action.question, c);
  }
  if (action.type === 'BUILD_PLAN') {
    const plan = await planner.build(c);
    await plans.save(c.id, plan);
    return planResponse(plan, c);
  }
  if (action.type === 'HANDOFF') {
    return handoffResponse(c);
  }
  return doneResponse(c);
}

硬预算：

- 最多 6 个追问；
- 每轮最多 1 次模型调用；
- 每轮最多 1 个工具调用；
- P95 响应 ≤ 2.5 秒；
- 模型失败 → 规则版；
- 不允许空转。

六、Case File：后端唯一事实来源
============================================================

前端不再维护事实。
浏览器只保存 caseId，不保存症状全文。

服务端 Case File：

{
  "caseId": "c_...",
  "sessionId": "s_...",
  "status": "intake|clarify|assess|plan|handoff|done|emergency",
  "patient": {
    "ageBand": "under18|18-39|40-64|65plus|unknown",
    "sex": "female|male|unknown",
    "pregnant": "yes|no|unknown",
    "anticoagulant": "yes|no|unknown"
  },
  "chief": "用户原话",
  "facts": [
    {
      "key": "location|onset|nature|severity|associated|history|meds|allergy",
      "value": "...",
      "source": "patient|rule|tool|model",
      "confidence": 0.0,
      "updatedAt": "..."
    }
  ],
  "unknowns": ["还在吃什么药"],
  "redFlags": [
    { "id": "stroke", "label": "疑似卒中", "source": "rule" }
  ],
  "urgency": {
    "rule": "emergency|soon|routine|observe",
    "model": "emergency|soon|routine|observe",
    "final": "emergency|soon|routine|observe",
    "reason": "一句话依据"
  },
  "plan": {
    "timeframe": "立即急诊|1-3 天|近期|可观察",
    "dept": "神经内科",
    "prepare": [],
    "questions": [],
    "whenToEscalate": []
  },
  "handoff": {
    "patientSummary": "...",
    "caregiverSummary": "..."
  },
  "trace": []
}

规则：

- 每个事实必须有 source 和 updatedAt。
- 模型推断的事实 confidence ≤ 0.7，并标“待确认”。
- 用户否定过的内容不得重复问。
- 用户说“不知道”写入 unknowns，不得反复问。
- 用户可查看、修正、删除。
- 分享使用服务端快照，不暴露内部 id。

============================================================
九、模型网关
============================================================

模型网关不是“转发”，而是“受控调用”。

要求：

1. Key 只从环境变量读取。
2. 前端不得直接调用模型。
3. 服务端自己从数据库拼 prompt，不信任前端 history。
4. 超时 25 秒，最多重试 1 次。
5. 连续失败 5 次，熔断 60 秒。
6. 强制 JSON 输出；Zod 校验。
7. 失败 → 规则版；不把脏数据写库。
8. 记录 task、model、latency、status、error_code、token 用量。
9. 不记录 chief、answer、prompt 原文。
10. 每个 prompt 有版本号，便于回归。

模型只负责：

- 生成追问；
- 整理摘要；
- 生成科室方向；
- 生成注意事项；
- 表达成用户能懂的话。

模型不负责：

- 红旗判定；
- 最终 urgency；
- 药名剂量；
- 诊断结论；
- 分享权限；
- 工具选择之外的系统操作。

输出审查：

- 科室白名单；
- 禁止“确诊/你得了/处方/剂量”；
- 禁止疾病概率；
- 禁止未知科室；
- 长度限制；
- 命中即丢弃，回退规则版。

============================================================
十、安全引擎
============================================================

安全引擎是服务端确定性模块，不依赖模型。

规则：

1. 红旗命中 → emergency。
2. finalUrgency = max(ruleUrgency, modelUrgency)。
3. 模型只能升级，不能降级。
4. 65 岁以上不给 observe。
5. 妊娠期出血/腹痛/头痛 → 升级。
6. 抗凝药 + 头部外伤 → 升级。
7. 关键信息缺失 → 不给 observe。
8. 卒中场景记录“最后正常时间”。
9. 急诊页必须 tel:120。
10. 不写“别吃药、别喝水”这种一刀切建议；
    改成“不要自行用药，听从 120 调度员指导”。

红旗至少覆盖：

- 呼吸困难；
- 意识改变；
- 大量出血；
- 疑似卒中（口齿不清、大舌头、半边发麻、走路偏斜）；
- 疑似心梗（压榨性胸痛、冷汗、晕厥）；
- 剧烈头痛；
- 抽搐；
- 严重过敏/喉头水肿；
- 孕晚期出血；
- 摔倒后头痛呕吐；
- 自伤/自杀风险。

否定句处理：

- 没有 / 无 / 否认 / 不伴 / 未出现；
- 不能把“没有胸痛”判成胸痛；
- 不能把“没有发烧”判成发热。

输出审查：

- 禁止“确诊”“你得了”“概率 N%”；
- 禁止药名 + 剂量 + 疗程；
- 未知科室回退全科医学科；
- 报告字段超长截断或拒绝。

测试：

- 30 条急诊句必须命中；
- 20 条否定句不得误判；
- 20 条高龄/妊娠/抗凝不得给 observe；
- 20 条越界/注入必须拒绝。

============================================================
十一、分享与权限
============================================================

分享必须是服务端快照，不是 `?share=1`。

流程：

1. 用户点“发给家属”。
2. 服务端生成 32 字节随机 token。
3. 数据库只存 SHA-256。
4. 保存 snapshot_json（脱敏摘要、进度、下一步、急诊信号）。
5. 24 小时过期。
6. 用户可撤销。
7. 家属打开 `/share/:token` 只读。
8. 不返回 sessionId、内部 id、模型信息、原始 prompt。

权限：

- owner：患者本人，可撤销/删除/导出。
- viewer：只读。
- contributor：可加问题，不能改事实/urgency。
- 所有操作写 audit_log。

验收：

- 无痕窗口打开同一份档案；
- 过期 410；
- 撤销 404；
- 越权 403/404；
- 分享内容不包含无关隐私。

十二、5 个功能，后端优先
============================================================

12.1 Care Kit 就医准备包

表：care_kits
工具：carekit.build(caseId)
API：POST /api/cases/:id/carekit
内容：8–12 项准备清单，可勾选，可打印。
安全：不写“必须空腹/停药”，只写“按医嘱”。
验收：勾选刷新保留；打印不溢出；家属只读。

12.2 Communication Card 沟通卡

工具：commcard.render(caseId)
API：POST /api/cases/:id/commcard
内容：全屏大字，听障沟通语句 + 关键信息 + 3 个问题。
安全：不含身份证/手机号/住址；离线可用；用户主动打开。
验收：飞行模式可开；1 米外可读；可切医生版/家属版。

12.3 Care Circle 家属协同

表：care_circle_members / care_circle_questions
工具：carecircle.invite/join/comment/revoke
API：
  POST /api/cases/:id/carecircle/invite
  POST /api/carecircle/join
  POST /api/carecircle/comment
  DELETE /api/carecircle/member/:id
权限：viewer 只读；contributor 只能加问题。
安全：默认 viewer；不能改 urgency；24h 过期；可撤销。
验收：无痕加入；viewer 不能写；撤销 404。

12.4 Teach-back 2.0 诊后回授

表：teachback_sessions
工具：teachback.create/evaluate
API：
  POST /api/cases/:id/teachback
  POST /api/teachback/:id/answer
内容：记录医生原话，生成 3–5 道点选题，确认患者听懂。
安全：只核对医生原话；不生成药名剂量；答错两次建议问医生/药师。
验收：医生说“一天一次饭前”，患者答“一天两次饭后” → 明确不一致。

12.5 Emergency Card 急诊卡

工具：emergencycard.render(caseId)
API：POST /api/cases/:id/emergencycard
内容：过敏、用药、基础病、联系人、最后正常时间。
安全：不写诊断；不写用药建议；不自动分享；离线可用。
验收：飞行模式可开；30 秒可读；卒中显示最后正常时间。

所有功能：

- 有 feature flag；
- 有权限检查；
- 有 trace；
- 有降级；
- 不新增独立导航；
- 关闭后主流程不受影响。

- CSP；
- X-Content-Type-Options；

日志：

- requestId；

部署：

- docker-compose + volume；
- .env.example；
- /healthz /readyz；

13. “我说话大舌头，右手没力” → emergency。
14. “肚子疼三天，没有发烧” → 不因“发烧”误升级。

23. Emergency Card → 飞行模式可开，显示最后正常时间。

十八、禁止事项
============================================================

- 不要只做一个 /api/chat 转发。
